Shine & Sing - Group 13, V9

The board uses saved templates trained on the eight group WAV recordings in
 data/recordings. No live enrolment is needed for the default build.

ED TESTS
Use the assignment workspace with Verilator 5.050 and Python 3.
  python3 -m pip install -r requirements.txt
  python3 tools/check_project.py --require-trained
  python3 tools/test_recordings.py
  python3 tools/test_saved_templates.py
  python3 tools/test_image_assets.py
  sh run_ed.sh
Run selected tests by adding their names, for example:
  sh run_ed.sh tb_recording_classifier tb_system tb_video_source
The test runner writes logs to build/. It removes compiled test executables
unless --keep-build is passed directly to tools/run_tests.py.

QUARTUS
Open shine_sing.qpf in Quartus Prime Lite 18.1 for the DE1-SoC board.
  python3 tools/check_project.py --require-trained
  quartus_sh --flow compile shine_sing
Program the newly generated output_files/shine_sing.sof. The repository does
not contain a SOF. Saved compilation and timing reports are in docs/evidence;
they are previous results, not a new compilation of this checkout.
After a successful fit, get detailed timing paths with:
  quartus_sta -t tools/report_timing.tcl

MODELSIM
Put ModelSim on PATH, or set MODELSIM_BIN to its executable folder.
  python tools/run_tests.py --sim modelsim

RECORDINGS AND TRAINING
Labels are ee, ah, oo and aw, in that order. Supply at least two independent
PCM WAV recordings for each vowel in data/recordings. Use names such as
 ee.wav, ee1.wav and ah-001.wav, or put takes in a vowel-named subfolder.
  python3 tools/train_recordings.py --samples data/recordings --sim verilator
For Windows/ModelSim, replace --sim verilator with --sim modelsim.
Training updates the templates, recorded-feature fixtures and metadata.
Run the tests again, then recompile Quartus before using the new templates.
For board-captured SignalTap data, use:
  python3 tools/train_saved_templates.py ee.csv ah.csv oo.csv aw.csv
The training metadata records validation results. The saved group-recording
validation contains many rejected frames; training-set results do not measure
accuracy on new speakers or recordings. Test microphone input on the board.

IMAGE FILES
The three images are assets/piano0, piano1 and piano2, in PNG, MIF and HEX form.
  python3 tools/import_image.py photograph.png --slot 2
  python3 tools/sync_mif_hex.py --slot 2
Use tools/prepare_assets.py only to rebuild the initial image memories and
lookup tables. It resets slot 2 to a copy of slot 1. Its optional --images
folder must contain ParallelPiano.png and ParallelPiano2.png.

VIDEO SIMULATION
  python3 tools/run_demo.py --sim verilator
Or render frames after running the demo test yourself:
  python3 tools/run_tests.py --sim verilator demo_visual
  python3 tools/run_demo.py --render-only
The saved pictures demonstrate the RTL video stream with synthetic audio
events. They are not screenshots of a physical monitor or live recognition.

FILES TO KEEP
rtl/ and quartus/: hardware, PLLs, VGA IP and pin assignments.
tb/: testbenches, recording-feature extraction and the video demo.
assets/: memory contents, image previews and expected test results.
data/recordings/: the group recordings used for training.
course_sources/: original files used by tests or kept to explain code reuse.
  Their original comments and licence notices are intentionally unchanged.
  Run python3 tools/audit_course_sources.py to update the reuse comparison.
tools/: build, training, image conversion, testing and packaging scripts.
docs/evidence/ and verification.json: saved results and their limitations.
assets/h95/ and tb_h95_classifier.sv: a separate classifier regression fixture.
  They do not measure the current group templates' accuracy on H95 data.

PACKAGING
  python3 tools/package_handoff.py
The ZIP is written to deliverables/ShineSing_V9_Group_Recordings.zip.
It includes the project, tests and data, and excludes build caches. A SOF is
included only when present and newer than the build inputs. Extract the ZIP
and run python3 tools/verify_bundle.py to check its file hashes.
